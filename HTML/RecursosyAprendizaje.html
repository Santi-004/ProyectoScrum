Glosario

Agile / Ágil: Metodología flexible que promueve entregas rápidas, colaboración constante y adaptación al cambio.
Análisis de calidad: Proceso de revisión de métricas y resultados para garantizar el cumplimiento de los estándares definidos.
Análisis estático: Evaluación automática del código sin ejecutarlo, utilizada para detectar errores o vulnerabilidades (ej. SonarQube, Coverity).
Artefactos (Scrum): Elementos tangibles del proceso ágil, como el Product Backlog, Sprint Backlog o Incremento.
Automatización: Uso de herramientas para ejecutar tareas o pruebas sin intervención manual, mejorando la eficiencia y la calidad.
Auditoría: Revisión formal de procesos o productos para verificar el cumplimiento de normas y requisitos.
Base de datos: Estructura utilizada para almacenar y gestionar información dentro del sistema.
Bug / Defecto: Error o falla detectada durante el desarrollo o las pruebas del software.
Caja blanca: Técnica de prueba que analiza la lógica interna del código para garantizar su correcto funcionamiento.
Caja negra: Técnica de prueba basada en la observación de las entradas y salidas del sistema sin conocer su estructura interna.
Ciclo de vida del software (SDLC): Conjunto de fases que guían el desarrollo de software desde la planificación hasta el mantenimiento.
Cobertura de pruebas: Porcentaje del código o funcionalidades que han sido verificadas mediante pruebas.
Código: Conjunto de instrucciones escritas en un lenguaje de programación que define el funcionamiento del software.
Control de calidad: Supervisión continua del proceso de desarrollo para asegurar que el producto cumpla con los estándares establecidos.
Defecto: Anomalía en el software que provoca resultados inesperados o incorrectos.
Desarrollo de software: Proceso estructurado para diseñar, programar, probar y mantener aplicaciones informáticas.
Diagrama de causa-efecto (Ishikawa): Herramienta de análisis utilizada para identificar las causas raíz de los problemas o defectos.
Diagrama de Pareto: Gráfico que ayuda a priorizar los problemas más importantes aplicando la regla 80/20.
Eficiencia: Capacidad del software para utilizar los recursos de forma óptima y cumplir su función con rapidez.
Estándar: Referencia o norma que define el nivel mínimo de calidad o desempeño esperado.
Gestión de calidad: Conjunto de procesos y prácticas destinados a garantizar que los productos o servicios cumplan con los requisitos del cliente.
Gestión de pruebas: Planificación, ejecución y seguimiento de las pruebas para asegurar la calidad del software.
Gestión de proyectos: Organización y control de los recursos y tareas necesarias para completar un proyecto de desarrollo.
Herramientas de calidad: Instrumentos que facilitan la medición, análisis y mejora continua (ej. JIRA, Trello, TestRail, SonarQube).
Hoja de verificación: Documento estructurado para recopilar datos de manera organizada y facilitar su análisis.
Implementación: Fase del SDLC en la que se desarrolla y codifica el software según el diseño aprobado.
Integración: Combinación de componentes o módulos del sistema para verificar su funcionamiento conjunto.
JIRA: Herramienta digital usada para la gestión de proyectos, seguimiento de defectos y metodologías ágiles como Scrum o Kanban.
Kaizen: Filosofía japonesa de mejora continua aplicada a la calidad y eficiencia de los procesos.
Kanban: Metodología visual para la gestión de tareas mediante tableros, tarjetas y columnas.
Mantenimiento: Etapa del ciclo de vida en la que se corrigen errores y se aplican mejoras al software en producción.
Metodología: Conjunto estructurado de prácticas, principios y herramientas que guían el desarrollo de software (ej. Scrum, Waterfall).
Métrica: Dato cuantitativo usado para medir el rendimiento, calidad o progreso de un proyecto.
Modelo en cascada (Waterfall): Enfoque tradicional de desarrollo con fases secuenciales donde cada etapa depende de la anterior.
Norma ISO 9001: Estándar internacional de sistemas de gestión de calidad que promueve la mejora continua.
Planificación: Primera fase del ciclo de vida del software donde se definen objetivos, recursos, costos y riesgos.
Pruebas de integración: Validan la interacción entre módulos o componentes del sistema.
Pruebas de humo: Pruebas iniciales rápidas que verifican si una nueva versión del software es estable.
Pruebas unitarias: Verifican que funciones o módulos individuales del software funcionen correctamente.
Proceso: Secuencia de actividades organizadas para lograr un objetivo determinado.
Producto de software: Resultado tangible del proceso de desarrollo, que debe cumplir con los requisitos del usuario.
QA (Quality Assurance): Aseguramiento de calidad; conjunto de actividades para garantizar que los procesos de desarrollo produzcan un software confiable.
Rendimiento: Medida de la velocidad y eficiencia con la que el software ejecuta sus funciones.
Requisito: Condición o funcionalidad que el software debe cumplir para satisfacer las necesidades del cliente o usuario.
Scrum: Metodología ágil basada en roles, eventos y artefactos para gestionar proyectos de desarrollo iterativos.
SDLC (Software Development Life Cycle): Modelo estructurado que define las fases del desarrollo de software para asegurar calidad y eficiencia.
Sistema de gestión de calidad (SGC): Conjunto de políticas, procesos y responsabilidades para asegurar la calidad organizacional.
Testing: Conjunto de actividades de prueba que verifican que el software cumple con los requisitos establecidos.
Trazabilidad: Capacidad de rastrear los requisitos y cambios a lo largo del desarrollo y pruebas del software.
Validación: Confirma que el software satisface las necesidades reales del usuario.
Verificación: Asegura que el software se haya construido conforme a los requisitos definidos.

Preguntas y Respuestas

Conceptos Generales

¿Qué es una metodología de desarrollo?

Una metodología de desarrollo es un conjunto de principios, prácticas y pasos que guían la manera en que se planifica, diseña, desarrolla y entrega un producto o sistema. Su objetivo es organizar el trabajo del equipo para lograr resultados más eficientes y de calidad.

¿Qué diferencia hay entre una metodología tradicional y una metodología ágil?

En una metodología tradicional (como Waterfall), las etapas del proyecto se siguen una tras otra, sin volver atrás. En cambio, las metodologías ágiles son flexibles: permiten revisar, mejorar y ajustar el producto en ciclos cortos, adaptándose a los cambios y al feedback del cliente.

¿Por qué las empresas usan metodologías ágiles hoy en día?

Porque permiten entregar valor de manera más rápida, mejorar la comunicación entre equipos y adaptarse a las necesidades del cliente sin tener que rehacer todo el proyecto.

¿Qué beneficios tiene trabajar con metodologías ágiles?

Entre los principales beneficios están: mayor flexibilidad ante cambios, entregas continuas, mejor comunicación entre los equipos, detección temprana de errores y mayor satisfacción del cliente.

¿Qué significa que un proyecto sea “iterativo” o “incremental”?

Iterativo significa que el trabajo se repite en ciclos cortos para mejorar continuamente el producto. Incremental significa que en cada ciclo se agrega una nueva parte funcional del sistema, hasta construir el producto completo.

¿Qué es Scrum?

Scrum es una metodología ágil que organiza el trabajo en ciclos llamados sprints. En cada sprint, el equipo desarrolla una parte del producto que puede probarse y mejorar. Se basa en la colaboración, la transparencia y la mejora continua.

¿Qué roles existen dentro de Scrum?

· Product Owner: define qué debe desarrollarse y prioriza las tareas.
· Scrum Master: guía al equipo, elimina obstáculos y asegura que se respeten los principios de Scrum.
· Equipo de Desarrollo: profesionales que diseñan, programan, prueban y entregan el producto.

¿Qué es un “Sprint” y cuánto dura normalmente?

Un Sprint es un ciclo de trabajo corto (generalmente de 1 a 4 semanas) donde el equipo desarrolla un conjunto específico de tareas o funcionalidades. Al finalizar, se presenta un avance real del producto.

¿Qué se hace en una reunión diaria o Daily Scrum?

Es una breve reunión de unos 15 minutos donde el equipo comenta qué hizo ayer, qué hará hoy y si hay algún impedimento que necesite resolverse.

¿Qué es el Product Backlog y para qué sirve?

Es una lista priorizada de todas las tareas, requerimientos o ideas que se deben implementar en el producto. Es el “mapa de trabajo” del equipo.

¿Qué diferencia hay entre un Sprint Backlog y un Product Backlog?

El Product Backlog contiene todas las tareas del proyecto. El Sprint Backlog es una selección de esas tareas que el equipo decide completar durante un sprint específico.

¿Qué significa una “retrospectiva” en Scrum?

Es una reunión al final de cada sprint donde el equipo analiza qué funcionó bien, qué se puede mejorar y qué acciones tomarán para el próximo ciclo.

¿Qué es la agilidad en el contexto de desarrollo de software?

La agilidad es una forma de trabajar que prioriza la colaboración, la adaptación al cambio y la entrega rápida de valor al cliente, más que seguir estrictamente un plan fijo.

¿Qué principios tiene el Manifiesto Ágil?

· Las personas y su interacción son más importantes que los procesos.
· El software que funciona vale más que la documentación extensa.
· La colaboración con el cliente está por encima de la negociación de contratos.
· Responder al cambio es mejor que seguir un plan rígido.

¿Por qué la comunicación constante es tan importante en los equipos ágiles?

Porque permite detectar errores, alinear objetivos, compartir avances y adaptarse a los cambios sin retrasar el desarrollo. La comunicación fluida es la base de un equipo ágil exitoso.

¿Cómo se manejan los cambios de requerimientos durante un proyecto ágil?

Los cambios se discuten con el equipo y el Product Owner. Si aportan valor, se agregan al Product Backlog y se planifican para un sprint futuro.

¿Qué pasa si no se logra completar todo lo planificado en un sprint?

Las tareas incompletas se reevalúan y se vuelven a priorizar en el siguiente sprint. Lo importante es aprender de lo ocurrido y mejorar la planificación.

¿Qué diferencia hay entre Scrum, Kanban y Waterfall?

· Scrum: trabaja con sprints fijos y roles definidos.
· Kanban: se basa en un flujo continuo de trabajo visualizado en un tablero.
· Waterfall: sigue un proceso lineal y cerrado, con etapas fijas.
Scrum y Kanban son ágiles; Waterfall es tradicional.

¿Cuál metodología usa menos documentación?

Scrum y Kanban requieren menos documentación formal, ya que priorizan la comunicación directa y los entregables funcionales.

¿Qué metodología es más flexible ante cambios?

Las metodologías ágiles (Scrum o Kanban) son más flexibles, porque permiten ajustar las tareas según el feedback del cliente o las nuevas necesidades.

¿En qué casos conviene usar una metodología tradicional?

Cuando el proyecto tiene requisitos muy claros desde el inicio, poco cambio esperado y requiere una secuencia estricta, como en proyectos de infraestructura o manufactura.

¿En qué se basa el proyecto que están desarrollando?

El proyecto se basa en principios ágiles, priorizando la entrega rápida de valor al usuario final mediante ciclos cortos de desarrollo y mejora continua.

¿Por qué eligieron aplicar Scrum o una metodología ágil en este proyecto?

Porque permite adaptarse a las necesidades del usuario, recibir feedback constante y garantizar que cada entrega aporte valor real y tangible.

¿Cómo se asegura la calidad del producto en cada sprint?

Mediante pruebas continuas, revisiones en equipo, control de calidad automatizado y la validación del Product Owner antes de cerrar cada sprint.

¿El usuario puede participar o dar feedback durante el proceso de desarrollo?

Sí. De hecho, el feedback del usuario es esencial para guiar las mejoras y asegurar que el producto final cumpla con sus expectativas y necesidades reales.

Actividades

Un equipo pequeño desarrolla una aplicación de finanzas personales con nuevas funcionalidades cada sprint según feedback de los usuarios

Metodología: Scrum
Por qué: Las entregas cortas, la priorización flexible y la colaboración cercana permiten adaptarse rápidamente a los cambios y responder al feedback.

Se debe crear un sistema de control de pacientes para un hospital, con alta criticidad y necesidad de trazabilidad de errores.

Metodología: Modelo en V
Por qué: Cada fase del desarrollo está vinculada con su respectiva prueba, lo que garantiza calidad, seguridad y validación constante.

Una empresa necesita desarrollar un sistema contable para auditorías fiscales. Los requisitos son claros y no se esperan cambios.

Metodología: Modelo en Cascada
Por qué: Los requisitos estables y bien definidos permiten seguir un proceso lineal, con documentación detallada y pruebas al final del proyecto.

Se desarrolla una app móvil del clima donde se agregarán gradualmente funciones como alertas, widgets y pronósticos.

Metodología: Incremental / Iterativo
Por qué: Permite entregar versiones funcionales por partes y añadir mejoras progresivamente, validando cada módulo antes de continuar.

Un estudio independiente desarrolla un videojuego con mecánicas que cambian constantemente según las pruebas de los jugadores.

Metodología: XP (Extreme Programming)
Por qué: Favorece iteraciones cortas, pruebas automáticas y programación colaborativa, ideal para proyectos que evolucionan rápido.

Se crea una app para gestión de tareas internas en una startup con prioridades cambiantes y necesidad de entregas rápidas.

Metodología: Kanban
Por qué: El flujo visual y continuo de tareas permite adaptarse fácilmente a cambios sin depender de ciclos fijos o sprints.

Se desarrolla un sistema de banca online que incorpora funcionalidades nuevas cada mes (transferencias, pagos, notificaciones).

Metodología: Incremental / Iterativo
Por qué: Permite construir el sistema por módulos, entregando versiones funcionales y mejorando progresivamente según las necesidades.

Metodología: Modelo en Cascada
Por qué: El enfoque lineal y la documentación formal aseguran una entrega final confiable, ideal cuando no se requiere feedback constante.

Se desarrolla un sistema de control de producción industrial con estrictas normas de seguridad y trazabilidad.

Metodología: Modelo en V
Por qué: La validación y verificación en cada fase aseguran el cumplimiento de estándares y la confiabilidad del sistema.

Metodología: Scrum
Por qué: Los sprints cortos y la colaboración continua con el cliente permiten ajustar el desarrollo con rapidez y eficiencia.

Metodología: Kanban
Por qué: La metodología visual y flexible permite reorganizar prioridades de forma continua sin interrumpir el flujo de trabajo.

Metodología: XP (Extreme Programming)
