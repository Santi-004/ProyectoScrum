¿Que es?

La calidad del software se refiere al grado en que un sistema, componente o proceso de software satisface los requisitos funcionales y no funcionales, asícomo las expectativas de los usuarios. No solo implica que el software"funcione", sino que lo haga de manera eficiente, segura, confiable, y que seafácil de mantener y usar.

Historia

-Edad antigua y artesanía: La calidad era responsabilidad del artesano, basada en su habilidad personal.

-Revolución industrial: Aparece la necesidad de control sistemático de calidad debido a la producción en masa.

-Décadas de 1920-1940: Surgen técnicas estadísticas de control de calidad (Shewhart, Deming).

-Después de la Segunda Guerra Mundial: Japón adopta enfoques de gestión de calidad más avanzados, impulsados por Deming y Juran, y se convierte en líder en calidad.

-Década de 1980: El enfoque se transforma en "gestión de calidad total" (TQM), integrando la calidad en todas las áreas de la empresa.

Actualidad: Se utiliza un enfoque estratégico basado en normas como ISO 9001, con un fuerte énfasis en el cliente, la sostenibilidad y la innovación.

Fundamentos Conceptos base

Métricas

Las métricas de calidad son valores numéricos que permiten evaluar el desempeño, comportamiento y estructura del software en distintas dimensiones. Son esenciales para:

-Detectar problemas en etapas tempranas del desarrollo

-Medir la evolución de la calidad a lo largo del ciclo de vida

-Tomar decisiones basadas en datos reales

-Mejorar procesos y productos

Estas métricas se alinean con las características de calidad definidas en normas como ISO/IEC 9126 e ISO/IEC 25000.

Estandares

Los estándares de calidad de software son normas internacionales que establecen criterios, modelos y mejores prácticas para garantizar que un producto de software cumpla con ciertos niveles de calidad. Ayudan a asegurar que el software sea confiable, seguro, eficiente, fácil de mantener y que satisfaga las necesidades de los usuarios.

Estándares más usados en calidad de software

-ISO/IEC 25000 (SQuaRE): Marco actual para definir, medir y evaluar la calidad del software.

-ISO/IEC 9126: Modelo clásico de calidad, base para ISO 25000.

-ISO/IEC 25010: Modelo actualizado que amplía ISO 9126 con características modernas.

-ISO 9001: Norma general para sistemas de gestión de calidad en organizaciones.

-IEEE 730: Estándar para planes de aseguramiento de calidad de software.

-CMMI: Modelo para evaluar la madurez de los procesos de desarrollo de software.

Técnicas de Aseguramiento de la Calidad

Tipos de pruebas de software

-Pruebas Unitarias: Verifican el correcto funcionamiento de componentes o módulos individuales.

-Pruebas de Integración: Aseguran que los módulos interactúan correctamente entre sí.

-Pruebas de Sistema: Validan el sistema completo contra los requisitos especificados.

-Pruebas de Aceptación: Se realizan para validar que el software cumple con las expectativas y necesidades del usuario final.

-Pruebas de Regresión: Verifican que los cambios o correcciones no afecten funcionalidades existentes.

-Pruebas de Usabilidad: Evalúan qué tan fácil y agradable es para el usuario utilizar el software.

-Pruebas de Rendimiento: Miden la capacidad del sistema bajo carga, tiempos de respuesta y estabilidad.

-Pruebas de Seguridad: Buscan vulnerabilidades que puedan comprometer la confidencialidad, integridad o disponibilidad del sistema.

Niveles de prueba

-Nivel Unitario: Se prueba cada unidad de código individualmente.

-Nivel de Integración: Se prueba la interacción entre unidades o módulos.

-Nivel de Sistema: Se prueba el sistema en su conjunto.

-Nivel de Aceptación: Se prueba el sistema desde la perspectiva del usuario final.

Técnicas de prueba

-Pruebas Manuales: Realizadas directamente por testers que interactúan con el software para detectar defectos.

-Pruebas Automatizadas: Utilizan scripts y herramientas para ejecutar pruebas repetitivas, aumentar cobertura y eficiencia.

-Pruebas Caja Negra: Se centran en probar la funcionalidad sin conocer la estructura interna del código.

-Pruebas Caja Blanca: Se basan en el conocimiento del código para diseñar pruebas que cubran rutas, condiciones y estructuras.

-Pruebas Exploratorias: Los testers exploran el software sin guiones predefinidos para descubrir problemas inesperados.

Herramientas de Calidad

Las herramientas de calidad facilitan la gestión, seguimiento y mejora del proceso de pruebas y del código en proyectos de software. Se clasifican en tres tipos principales:(cada una tiene el link a su pagina)

Herramientas de gestión de pruebas:

Ayudan a planificar, organizar y ejecutar casos de prueba, además de registrar resultados y reportes. Ejemplos:

-TestRail

-Zephyr

-qTest

Herramientas de gestión de pruebas:

Permiten registrar, gestionar y priorizar los errores o incidencias detectadas durante las pruebas. Ejemplos:

-Jira

-Bugzilla

-Redmine

Herramientas de gestión de pruebas:

Realizan análisis automático del código para detectar vulnerabilidades, bugs, problemas de estilo y medir métricas de calidad. Ejemplos:

-SonarQube

-Coverity

-Jenkins (para integración continua y ejecución automática de pruebas).
